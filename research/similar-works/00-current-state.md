2026-11-03。這份是「類似作品研究」的第 0 章:先把我們自己的專案看清楚,後面的比較和改進建議才有根據。

## 一、架構

### 1. 檔案與載入順序
沒有 build step,全部是 `index.html` 依序載入的 plain `<script>`(`index.html:73-95`),每個檔案都是一個 IIFE,透過 `window.*` 全域物件互相溝通。

| 2 | `asset/3d/assets-*.js` ×7 | 756 KB(資料夾) | 隊友的資產庫(西門町/大稻埕 1980s–2000s 店面) |

### 2. 模組之間怎麼說話
- **一個數字驅動一切**:`progress`(0…1)。時代、年份、標籤、照片、101 上的男人都只讀這個數(`app.js:1143-1160`, `app.js:1522-1573`)。
- **導覽模式**:`progress` 來自 `window.scrollY`,加阻尼(`app.js:1537-1540`),再由 `placeCamera(u)` 沿 `DATA.CAM` 六個關鍵影格的曲線放鏡頭(`app.js:1111-1131`, `data.js:132-145`)。
- **走路模式**:`app.js` 每幀呼叫 `WALK.update()`,由 walk.js 放女孩和鏡頭,再把「她所站位置等於捲動多少」寫回 `WALK.u`(`walk.js:417-420`, `app.js:1533-1535`)。walk.js 檔頭明說「app.js 一行都沒為走路重寫」(`walk.js:18-21`)——走路模式是**寄生在捲動影片上**的。
- 其他模組讀全域:`memories.js` 讀 `WALK.pos/where/section()`、`SQUARE.makeLantern/board`;`square.js` 讀 `window.__music` 來讓卡拉OK的人跟著搖;`photos.js` 讀 `window.__fog.progress/era`。
- **共有 3 條獨立的 `requestAnimationFrame` 迴圈**:`app.js:1572`、`memories.js:323`、`photos.js:192`,加上 music.js 的 250 ms 計時器。後兩者不和主迴圈同步,投影 DOM 泡泡時用的可能是上一幀的鏡頭。

### 3. 渲染管線
1. **全域改寫 three.js shader chunk**:霧(方向性霧,`app.js:82-112`)、色調映射(只作用在亮度的 ACES 曲線,`app.js:186-195`)。所有材質都繼承這些改寫。
2. 光:半球光(陰影染紫,`app.js:207-215`)+ 一盞會投影的太陽,PCFSoft、桌機 2048 / 手機 1024,每幀跟著鏡頭移動陰影框(`app.js:225-238`)。
3. 環境貼圖:canvas 畫的天空經 PMREM(`app.js:255-283`)。
4. 頂點烘焙 AO(`app.js:135-166`)。
5. 每個時代切換時,所有 `part()` 方塊在 500 ms 內改高度和顏色(`app.js:1004-1037`);走路廣場則再疊一層「黃昏係數」`WALK.dusk`(`app.js:1050-1062`)。
6. **離屏 render target → 全螢幕後製**:描邊、色階化(目前 `uPrint` 全為 0,`data.js:29-35`)、顆粒、暗角、時代交界的照片疊印、暖色調(`app.js:1168-1240`)。
7. 首幀「暖機」:把整個場景全部設為可見,`renderer.compile` 並畫一次,避免第一次進入時代時卡頓(`app.js:1511-1518`)。
8. 發光物一律 `toneMapped: false` + 加法光暈 sprite,不用真的點光源(`square.js:13-14`)。

### 4. 走路模式 vs 捲動導覽

| | 走路模式(預設) | 導覽(`?tour=1` / `?year=`) |
|---|---|---|
| 入口 | 直接進廣場;第一次來看到歡迎卡(`walk.js:206-242`, `walk.js:466`) | 歡迎卡或右下按鈕「Guided tour」(`walk.js:180`, `walk.js:322-332`) |
| 操作 | WASD/方向鍵、Shift 跑、拖曳轉鏡頭;手機為右下搖桿(`walk.js:244-285`) | 捲動、鍵盤翻頁、觸控捲動(`app.js:1478-1501`) |

## 二、訪客體驗,一步一步

1. **載入**:三十多個 script 依序下載;字型 `font-display: block`(`style.css:10-15`),字型到之前文字是隱形的。首幀做暖機編譯。
2. **歡迎卡**(只在第一次):英文為主「Walk into a decade of Taipei.」,三個門的色卡、「Start walking / Guided tour」(`walk.js:211-227`)。
3. **廣場,黃昏**:鏡頭從南側低角度看大榕樹(`walk.js:307`)。左上角面板「廣場 THE SQUARE · Three gates, forty years. West 西門町 · North 大稻埕 · East 信義」(`walk.js:173-174`)。中間提示操作,4 秒後在第一次移動後淡出(`walk.js:384`)。
4. **廣場裡能做的事**:
   - 走近卡拉OK站按 E(或點泡泡):播放/換下一首該年代的歌(`square.js:899-939`)。
   - 走近公布欄按 E:打開「Everyone's memories」清單(`memories.js:162-181`, `square.js:754-792`)。
   - 象棋、老人茶、土地公廟、金爐、香腸攤、鴿子——**全部只能看**,沒有互動;人物只在原地擺動頭或手臂(`square.js:877-883`)。
   - 「+ Leave a memory」按鈕隨時可按(`memories.js:262-265`)。
5. **穿過門**:走進門的光幕 → 畫面淡黑 320 ms → 出現在該段街道起點(`walk.js:288-302`, `walk.js:403-407`)。
6. **街段裡**:一條寬約 17 單位的走廊,兩側是三段街景;左上顯示章節與年份;建築旁有照片熱點環(`photos.js:190-226`);飄著的紅/橘燈籠是記憶,走近出現「A memory · E」泡泡(`memories.js:295-324`)。段尾的拱門通往下一段或回廣場(`walk.js:145-161`)。
7. **信義段的盡頭**:停在 101 前(`walk.js:48`),可以把鏡頭往上拉看爬樓的人(`walk.js:448`)。
8. **導覽影片**:捲動穿越 40 年,大字逐句出現,在時代交界有一張真實老照片淡入淡出(`app.js:1280-1293`),最後是男人攀上 101 頂端揮手,「Keep climbing, just like the man on Taipei 101」(`data.js:63-70`, `app.js:375-402`)。

## 四、弱點與風險(誠實版)

### A. 技術

**效能**
1. **整條街 + 廣場常駐同一個場景**:三個時代的所有幾何、七份資產庫、廣場,全部在載入時建好、一直存在,只靠 `visible` 切換(`index.html:76-82`, `app.js:1030-1036`, `walk.js:163-166`)。記憶體和首幀暖機成本隨內容線性成長(`app.js:1511-1518` 把所有物件設可見再編譯)。
2. **每幀固定成本高**:PCFSoft 陰影圖(桌機 2048)每幀重畫(`app.js:225-228`),再加全螢幕後製五次取樣(`app.js:1186-1192`)。沒有「靜止時不重畫」,也沒有依 FPS 自動降畫質;手機只做了 pixel ratio 1.5 和陰影 1024(`app.js:174`, `app.js:228`)。
3. **廣場樹冠**:研究文件寫約 800 張葉片卡(`research/banyan-square/README.md` 第二節),程式實際是桌機 55×38 = 2090、手機 1200 張,alphaTest + 雙面 + 參與陰影深度 pass,`frustumCulled = false`(`square.js:256-280`)。alpha-test 的過繪在手機 GPU 上是典型瓶頸。
4. **卡拉OK 螢幕每 0.12 秒重畫 canvas 並重新上傳貼圖**(`square.js:895-897`)。
5. **記憶燈籠不 instancing**:每筆記憶 = 1 個 Group、5–6 個 mesh + 1 個 sprite(`square.js:134-147`),年份不同就多一張 512×256 canvas 貼圖(`square.js:104-125`)。上限 500 筆時約 3000 個物件與數十張貼圖。
6. **三條 rAF 迴圈**互不同步(見一.2),每條都各自做投影與 DOM 寫入。
7. **從未在真手機上量過**:HANDOFF 待辦第 8 項(`HANDOFF.md` Open items 8)寫明只用 headless Chrome 390×844 檢查過;rubric 的「效能 5 分」全是桌機 60 Hz 上限下測的(`docs/RUBRIC.md` Scoring 3)。廣場與走路模式**完全沒有被 rubric 評過**。

**可維護性**
8. `app.js` 是 1610 行、108 KB 的單體,渲染、霧、光、女孩、男人、大字、HUD、捲動、測試探針都在裡面。
9. **全域耦合 + 載入順序依賴**:`window.SCENE/RIG/WALK/SQUARE/__fog/__music/__photos`;每個檔案開頭用 `if (!window.X) return` 靜默放棄(例如 `walk.js:24`, `memories.js:16`),順序錯了不會報錯,只會少一塊。
10. **全域改寫 three.js shader chunk**(`app.js:82-112`, `app.js:186-195`)綁死 r149(2022 年版本);升級 three.js 幾乎一定要重寫。
11. **重複的工具函式**:canvas 招牌 `sign()`(`walk.js:82-91`)與 `canvasTex()`(`square.js:44-51`)、`box()`、字型常數(`walk.js:93-94`, `square.js:38-39`)各寫一份;`asset/3d/three.min.js` 是第二份 three.js。
12. 沒有自動化測試或 CI(`.github/` 下沒有 workflow);測試靠 `window.__fog` 探針和手動 headless 截圖(`app.js:1596-1604`, `HANDOFF.md` How to test)。探針留在正式頁面。
13. 文件過時:`HANDOFF.md` 的「Not done on purpose」仍寫「No free camera, no menu, no save state」與「one verb: scroll」,和現在的走路模式矛盾;walk.js 註解仍稱女孩為張君雅小妹妹(`walk.js:5`)。

**手機**
14. 互動提示寫的是鍵盤:泡泡上永遠顯示「E」鍵帽(`memories.js:135`, `square.js:902`),觸控使用者看不懂。
15. 右下搖桿 118 px、右側 42% 高度的直排按鈕、左下音樂膠囊(`walk.css:70-79`)——小螢幕上 HUD 佔掉大量畫面,而且「拖曳任何地方轉鏡頭」和點燈籠共用同一個手勢(`walk.js:259-270`, `memories.js:280-291`,靠 6 px / 500 ms 判斷)。
16. 沒有處理橫豎切換以外的狀況(瀏海安全區、`visualViewport` 鍵盤彈出時表單位置);表單是固定定位 DOM。

### B. 體驗

**上手**
17. **介面幾乎全英文**:`<html lang="en">`(`index.html:2`),歡迎卡、按鈕、表單、提示都是英文,中文只是副標。目標觀眾是「記得台北的人」,這是第一道門檻。
18. 歡迎卡只在第一次出現(`walk.js:242`),之後沒有任何說明或地圖;三道門只靠「西/北/東」方位辨認,廣場裡沒有指引視線的動線或小地圖。
19. 預設是走路而非影片,但**作品最強的情緒弧線在導覽裡**;走路的人可能從沒看過大字和結尾。

**情緒**
20. 走路模式**拿掉了所有大字**(`walk.css:8`, `app.js:1548-1549`),三段街只是場景,沒有「我們長大了」的敘事節拍。
21. 標語是「Three generations. One street.」(`index.html:41`)、大字說「We grow older / We carry responsibility」(`data.js:46-56`),但女孩 40 年都是小孩,沒有任何成長、換裝或世代交替的視覺。
22. **走路時 101 的高潮大概看不到**(推算):走到信義段盡頭時,`WALK.u` 由 `uAtZ(z+18)` 推得(`walk.js:420`),依 `data.js:132-145` 的鏡頭路徑大約只到該章節的 75% 左右,低於男人登頂的 `CLIMB_TOP = 0.93`(`app.js:370`);而走路鏡頭往上最多只抬到約 15 單位高(`walk.js:448`)。也就是說,README 所說「在 101 腳下看他揮手」在走路模式多半做不到,需實測確認。
23. 時代交界的老照片疊印是為捲動設計的(`app.js:1280-1293`);走路模式下 `progress` 被夾在章節起點附近(`walk.js:419`),照片可能在走進大稻埕/信義的前幾步淡淡疊在畫面上,也可能完全沒機會出現,兩種都不是設計過的時刻(推算)。
24. 沒有環境音(人聲、機車、廟口、雨),HANDOFF 明寫「no sound effects」;聲音只有 YouTube 歌,而且 YouTube 會插廣告(`music.js:31-36` 自己承認無法移除)。

**互動深度**
25. 動詞很少:走、看、讀燈籠、按 E 換歌、留言。廣場的長者、象棋、香爐、攤車都不能互動;街段是左右 ±8.4 的走廊(`walk.js:36`),不能進店、不能轉進巷子。
26. 記憶只能「讀」,不能回應、按讚、收藏、跟著年份或地點瀏覽;沒有分享自己燈籠的連結。
27. 留言時的年份不受所在時代限制(只有 placeholder,`memories.js:226`, `memories.js:240`):站在 2020 年代的信義也能留 1962 年的記憶,燈籠會掛在錯的時代。

**內容缺口**
28. 時間只有 1985–2027,而且中間二十年(2000–2019)只演春節一個場景(`data.js:31-33`);廣場允許 1950 年起的記憶(`memories.js:26`),但沒有對應的街景。
29. 台北人共同記憶裡的大物件缺席:捷運(1996 木柵線)、夜市、便利商店、機車潮、颱風天、公車、檳榔攤等都沒有出現。
30. 三段之間各自封閉,廣場又是「時間之外」,沒有讓人感覺「這是同一個城市隨時間改變」的空間連結(導覽才有)。
31. 年代錯置已被 rubric 指出(1989 畫面出現 NOKIA、Sony Ericsson),被列為「等 CJ 決定」(`docs/RUBRIC.md` 第 1 名最低分、`HANDOFF.md` Open items 3);`scene-red.js:329`, `scene-red.js:876` 註解顯示已部分清除,完成度不明。

### C. 產品

**記憶流程**
32. **目前正式站其實沒有連上共用資料庫**:`memories-config.js:14-15` 的 URL 與 key 都是空字串,所以 `ONLINE = false`(`memories.js:19`)。每位訪客只看得到 2 盞種子燈籠和自己留的,公布欄寫著「Leave the first memory here」(`square.js:771`)。作品的核心承諾「一個能承載大家記憶的頁面」尚未成立。
33. Supabase 免費方案的專案在一段時間沒有活動後會被暫停;這是一個要人記得維護的外部依賴,一旦暫停,`fetchApproved` 只會在 console 印警告(`memories.js:87`),頁面靜默退回只有種子。
34. 讀取一次最多 500 筆、沒有分頁、全部變成燈籠(`memories.js:83-86`);規模一大就同時是效能問題(見 A.5)和閱讀問題(一條街掛幾百盞燈籠)。
35. 廣場的記憶沒有空間意義:按「Leave a memory here」,表單說「留在這裡」,但廣場記憶不會掛在那裡,只會進公布欄(`memories.js:56-63`, `memories.js:190`)。
36. 送出後訪客只看到「讀過後會亮」(`memories.js:254`);沒有回執、沒有通知、無法確認自己的燈籠是否上線,也不能編輯或撤回。

**審核**
37. 審核只能在 Supabase 後台的 Table Editor 手動改 `status`(`docs/MEMORIES.md` Approving memories);沒有審核介面、沒有新投稿通知、沒有檢舉按鈕。
38. 防濫用全在前端:蜜罐欄位、2.5 秒最短停留、30 秒一筆(`memories.js:237-243`),關掉 JS 或直接打 REST API 就能繞過。伺服器端沒有頻率限制,文件自己寫下一步要加 Turnstile(`docs/MEMORIES.md` 最後一段)。
39. **照片 bucket 是公開的,而且任何人都能上傳**(`supabase/schema.sql:42-50`):待審照片只靠 UUID 檔名難猜來保護(security by obscurity);任何人都能用 anon key 上傳 2 MB 檔案而不建立記憶,等於免費圖床。照片先上傳、再寫資料列(`memories.js:116-126`),寫入失敗就留下孤兒檔。
40. 只有一個勾選框的同意聲明(`memories.js:200`),沒有隱私說明、聯絡/下架管道、資料保存期限;收集姓名與照片在台灣個資法下至少需要告知事項。
41. 角色與品牌:女孩源自商業吉祥物張君雅小妹妹(`CHANGELOG.md:21`, `app.js:804`),已改成通用小學生但文件仍沿用名稱;街景有真實品牌招牌。公開推廣前值得檢查一次。

## 五、一句話總結
視覺和考據下了很深的工夫(每棟建築都有真實出處、每張照片都有授權、每首歌都對到副歌),但目前的作品是**一部做得很細的捲動短片,外面接了一個還沒長出玩法的走路殼**:走路模式拿掉了敘事,記憶系統還沒上線,手機從未實測,而所有東西都疊在一個 1600 行的 `app.js` 和一個常駐的大場景上。
